# Independent reality review — portable GLB resource boundary

Дата: 2026-11-04. Проверены `telegram-portable-v1-disposition-2026-11-04.md` (§ portable GLB и alias route), AD-30 и фактические V1 call sites. Проверка read-only; код и canonical документы не менялись.

## Вердикт: PASS WITH SOURCE-OWNER DISPOSITION AND EVIDENCE PENDING

- `static-glb-import.ts` проверяет 25 MiB до GLB parsing, а затем version/chunk bounds, URI, static content/extensions, geometry/node/material/texture и decoded-pixel budgets. `catalog-media-validator.ts`, пользовательские import/placement и portable smoke вызывают прежний public preflight. Companion правильно сохраняет 25 MiB, порядок и результаты прежних call sites; выделение общей read-only проверки с явным portable envelope cap не является admission или повышением custom limit.
- `project-and-backup-contract.md` и `backup-feasibility-policy.ts` действительно содержат 50 MiB per resource / 180 MiB aggregate; `asset-import-contract.md` отдельно фиксирует provisional 25 MiB hard и применение меньшего лимита при пересечении. Companion не объявляет 25–50 MiB custom GLB допустимым для новой Durable admission и передаёт вопрос применимости к точному recovery/import владельцу source policy.
- `PortableBackupReadRenderSmokeCheck` проверяет exact key/length/hash, вызывает текущий preflight и строит `projectRectangularRoomForWebGl`; это не полноценное доказательство GLB decode, GPU, no-network security или physical device acceptance. Companion различает эти границы и сохраняет последующие security/decoded-resource проверки. Структурный preflight сам по себе не доказывает все требования security policy, в частности нельзя объявить только по нему закрытыми JSON-depth/morph/decode/worker memory ограничения из asset contract.
- Существующие smoke, feasibility и hydration paths сравнивают SHA string с raw resource key; V1-only bitwise SHA-256 comparison требует строгих 64 ASCII hex, проверки каждого из исходных case-sensitive keys и bytes/length, а также согласованной сквозной реализации на каждом перечисленном companion этапе. Сравнение bytes между case aliases перед dedup не допускает подмену; lowercase PPJ и browser/catalog правила не меняются.
- Приведённые boundary, hostile GLB, alias, crash и physical evidence пока не запускались этим review. Новый способ не является реализованным или допуском S3; недостаточность 50-MiB envelope для самостоятельного решения 25-MiB source policy остаётся явной.
