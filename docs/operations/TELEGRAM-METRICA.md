# Статистика открытий Telegram Mini App

## Обычная сборка

До первого учитываемого входа и в настройках можно выключить статистику на устройстве. Суточный подсчёт открытий по умолчанию включён. Для измерения повторных открытий пользователь отдельно разрешает приложению помнить предыдущие открытия на этом устройстве. При следующем подходящем входе приложение может отправить дополнительный пустой запрос. Закрытие формы ничего не разрешает. Приложение не связывает открытия между устройствами и не передаёт приёмнику редакцию лицензии, время согласия, аккаунт, Telegram ID, файлы или планировку.

| Показатель | Как читать |
| --- | --- |
| Сумма параметра `tma_opens` | Число полученных сигналов открытия за московские сутки. Сигналы от пользователей с выключенной статистикой отсутствуют. |
| Сумма параметра `tma_repeat_opens` | Число полученных сигналов добровольного повторного использования на том же устройстве. Это количество открытий. Для доли удержанных людей этих данных недостаточно. |

Одна суточная запись поступает в отдельный счётчик `114493478` с общим служебным ClientID. На дашборде «Открытия TMA по дням» прежний виджет показывает сумму `tma_opens`. Для повторного использования нужен отдельный виджет суммы `tma_repeat_opens`, его отображение проверяют после первой фактической доставки. Новая схема прекращает передачу псевдонима участника в индивидуальный счётчик. [Дашборд суточных открытий](https://metrika.yandex.ru/dashboard?id=114493478&dashboardId=47721ca6-23fd-42ca-825a-fd04a9ca1417)

Для перехода администратор сначала обновляет коллектор, сохраняет существующую SQLite, проверяет готовность приватного сервиса и таймера, затем выпускает версии сайта и каталога. В состав обычного архива сайта коллектор не входит. Старая конфигурация, физическая проверка Telegram Desktop и её данные относятся к прежнему релизу. Текущий статус публикации подтверждается отдельной записью о выпуске. [Установка, сверка и выключение](../../scripts/analytics/README.md)
