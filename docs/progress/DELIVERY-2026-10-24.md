# Доработка InteriorsEditor после возвращения к проекту

Дата: 24 октября 2026. Это отчет о реализации после исходного [аудита](PROJECT-RESUME-2026-10-24.md). Числа из первоначального аудита относятся к состоянию до этих изменений.

## Как открыть на телефоне

Рабочий HTTPS: **https://dry-jeff-mere-settle.trycloudflare.com**. На Mac работают собранная PWA, Kotlin catalog control plane и PostgreSQL 18.4; web обращается к настоящему backend через один origin.

1. Открыть адрес на телефоне. На iPhone — Safari → «Поделиться» → «На экран Домой» → «Добавить», с включенным «Открывать как веб-приложение», если настройка предлагается. На Android — Chrome → меню → «Установить и создать ярлык» → «Установить». [Apple](https://support.apple.com/en-gb/guide/iphone/iphea86e5236/ios), [Google](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=ru).
2. Открыть приложение с новой иконки, создать проект и контур. Первую загрузку приложения и выбранных моделей выполнить с интернетом.
3. Проверить каталог: раковина относится к сантехнике, настенное бра — к освещению и сохраняет привязку к стене. После подтверждения дождаться «Сохранено», закрыть и открыть проект, сравнить План и 3D.
4. Импортировать собственный GLB, поставить предмет, убрать только его карточку из каталога. Предмет в проекте должен остаться; повторный импорт возвращает карточку.
5. Скачать `.interiors`. Закрыть PWA, включить авиарежим, открыть с иконки и проверить сохраненный проект и уже подготовленные предметы. Импортировать копию как отдельный проект.

Mac должен оставаться включенным, с открытой крышкой и интернетом. Для работающего web-процесса включено предотвращение автоматического простоя. Туннель временный: после его перезапуска адрес может измениться, а у другого адреса будет отдельное хранилище. Важные проекты переносить через `.interiors`; Safari и установленная PWA также могут хранить проекты отдельно. Данные сайта для обновления очищать не нужно.

Если уже открывалась прежняя сборка, дождаться предложения обновления и применить его после сохранения правок. Инструкция повторного запуска и дальнейшего постоянного размещения — [runbook](../operations/PHONE-AND-RELEASE-RUNBOOK.md).

## Реализованные изменения

| Направление | Что изменилось для пользователя и разработки |
| --- | --- |
| Каталог | Чистая сборка содержит четыре прежде отсутствовавшие небольшие GLB и полный набор из 20 ресурсов. Исправлены диапазоны загрузки до конца файла, HEAD, недопустимые Range и методы. Все ranged запросы отправляют правильный Accept. |
| Настенные модели | Каталожный предмет с wall anchor проходит существующий настенный preview и atomic publish. Размеры берутся из проверенного описания; host/side/offset/elevation сохраняются, ошибочная напольная постановка исключена. |
| Карточки | Показаны действительная категория и способ крепления. Фильтрация и поиск используют те же сведения, что размещение. |
| Backend | Добавлены только проверенные Gradle checksum metadata, strict dependency verification сохранена. Поднят PostgreSQL 18.4 и живой каталог из 12 предметов; opt-in browser scenario обновлен под фактическую публикацию. |
| Мобильные диалоги | Rename вынесен в отдельный native dialog. Restart и выбор цвета используют общий native confirmation. Фокус удерживается в диалоге, возвращается после отмены; pending/busy/error/retry остаются внутри соответствующего действия. |
| Мобильная геометрия UI | Шапка и нижние действия растут под увеличенный текст. Положение подсказки 3D и камеры учитывает фактическую высоту шапки. Проверяются узкий короткий экран, увеличение текста и доступные области касания. |
| Несохраненная правка | Добавлен самостоятельный versioned `.interiors-recovery.json`, честно помеченный unpublished. Он содержит точный candidate и доступные проверенные ресурсы. Полный файл восстанавливается через существующий импорт в новый проект, сохраняя исходный. |
| Ресурсное восстановление | Исходные GLB и полная `.interiors` доступны из одной панели; exact backup repair работает для current и session history, без новой Revision от ремонта байтов. При валидной геометрии показан проверенный read-only план с временно скрытыми недоступными моделями. |
| Межоконная надежность | Запуск другого окна сохраняет недоказанные staging roots. Уже разделяемые байты защищаются атомарно, поэтому отмена первого владельца не может удалить ресурс чужой опубликованной версии. Pending GLB/import сохраняет точные байты для retry/recovery. |
| Своя библиотека | Добавлено постоянное удаление карточки через tombstone и явное возвращение повторным импортом. Это не удаляет объекты из проекта, history roots или bytes для backup; автоматическое обнаружение старого проекта не отменяет удаление карточки. |
| Сопровождение | Отдельные PlanProjection и presentation helpers, общий pipeline восьми публикационных команд; исключен runtime import cycle renderer. Добавлена проверка границ слоев через compiler API и негативные fixtures. |
| Проверки и эксплуатация | README/index приведены к финальному READY и 35/35 Alpha stories. Добавлены команды проверок, SHA-pinned CI с read-only token, release/rollback/phone runbook и протокол реальной пользовательской проверки. |

Канонические SPEC, PRD, Architecture Spine и геометрические инварианты не переписывались. Коммиты и загрузка репозитория на внешний Git-сервис не выполнялись.

## Честный остаток roadmap

- Реальная приемка на iPhone/Android, проверка скорости, памяти, экранной клавиатуры и офлайн-жизненного цикла. Эмуляция браузера не закрывает измерения на физических устройствах.
- Пользовательское исследование по метрикам PRD. [Протокол](../validation/ALPHA-USABILITY-PROTOCOL.md) подготовлен; результаты с участниками не выдумывались.
- Постоянный HTTPS origin, hosting web/backend и эксплуатация PostgreSQL. Доступных учетных данных/домена нет; текущий Quick Tunnel не заменяет этот этап.
- Полный global orphan GC. Неопределенные staging roots теперь удерживаются консервативно; автоматическое удаление требует доказательства отсутствия всех live/durable/history roots. Удаление карточки каталога не освобождает эти байты.
- Для библиотеки остается отдельная проверка совпавших asset identifiers у разных импортированных карточек; текущий API удаления ориентирован на identifier. Это не удаляет bytes, Project или историю.
- Завершение Alpha+ Epic 9 требует его нормативного corpus и физических ресурсных бюджетов. Реализованные регистрация, отмена, повторное использование, удаление карточки, backup и repair улучшают этот этап, но сами по себе не закрывают все 9.1–9.3.
- Legacy `swingSide` сохранен совместимым. Новая проверка переносит через настоящий ZIP три исторических случая: поле отсутствует, `left`, `right`; импорт создает новый Project, исходная версия неизменна. Удаление этого поля из старых Revision или автоматическое переписывание checksum не выполняется: для окончательной миграции нужен отдельный форматный переход и corpus старых копий.
- Следующий PlanGraph kernel integration и дальнейшее разбиение AppShell выполнять отдельными вертикальными срезами. Текущее извлечение не меняет жесты и геометрию; AppShell сокращен примерно с 14 000 до 10 048 строк и все еще крупный. Повторный Fallow 3.35.0 показывает 6,62% дублирования против исходных 6,94%; это вспомогательный статический сигнал, не runtime coverage.
