# Повторная проверка загрузки каталога — 2 ноября 2026

Причина текущего отказа подтверждена инфраструктурой: прежний адрес `pope-controversy-tube-geek.trycloudflare.com` перестал разрешаться, а живой процесс cloudflared получал `Unauthorized: Tunnel not found`. Локальные приложение и API каталога продолжали отвечать. Уже загруженная PWA могла показывать сохранённый интерфейс, но новые сетевые загрузки по прежнему адресу завершались ошибкой. [Фрагмент журнала](expired-tunnel.log).

Тоннель перезапущен: [новый телефонный адрес](https://gym-departmental-classical-trustee.trycloudflare.com). Код приложения и production-сборка `ccdd13662cdca379` не изменялись. Хранилище проектов не очищалось. Новый origin использует отдельное браузерное хранилище; перенос старого проекта выполняется штатными экспортом и импортом, автоматически данные между адресами не объединяются.

## Выполненные проверки

- Все **12 моделей** полностью получены через новый внешний HTTPS теми же диапазонами по 1 MiB. Проверены `206`, `Content-Range`, `ETag`, точное количество байт и SHA-256 каждой модели. Самая крупная модель — 21 404 360 байт. [Машинный результат](resource-checks.json), [лог](resource-checks.log), [проверяющий сценарий](check-resources.py).
- **2/2 настоящих live UI-сценария** через новый тоннель: кровать на полу и бра на выбранной стене. Проверяется не только доступная кнопка: реальная загрузка GLB, предварительное размещение, подтверждение, одна новая ревизия, точная привязка, размеры, версия каталога, SHA сохранённых локально байтов, reload и повторное открытие. Ни HTTP fake, ни подмена каталога не используются. [Лог с TypeScript и lint](public-live.log).
- **3/3 сценария отказов/повтора** на той же production-сборке локально: большой файл по Range, отказ загрузки модели с отменой/повтором, недоступная публикация каталога с восстановлением. Сохранённый проект остаётся неизменным. [Итоговый лог](retry-final.log).
- **12/12 моделей подготовлены в мобильном интерфейсе** по новому HTTPS: видимое «Готово для размещения», доступная для настоящего нажатия кнопка, совпадающие размер/SHA метаданных; все опубликованные изображения декодированы. Ошибок страницы, консоли и запросов не зафиксировано. [Результаты](ui-all-models/results.json), [снимки и методика](ui-all-models/README.md). Первоначальная ошибка ad-hoc harness ожидала картинку в скрытой после выбора карточке; в итоговом прогоне проверяется реальный видимый preview. Это не считалось дефектом приложения.

## Изменения тестов

`catalog-control-plane-live-e2e.spec.ts` прежде завершал проверку на доступности «Показать на плане». Теперь оба типа размещения проходят до сохранения и повторного открытия, с точной проверкой ресурсов и истории.

В двух прежних сценариях ошибок каталога исправлено ожидание подготовки: исходное число ревизий читалось сразу после нажатия «Создать контур», иногда раньше его сохранения. Из-за этого тест ошибочно сравнивал одну ревизию пустого проекта с двумя ревизиями уже созданного контура. Теперь перед чтением исходного состояния тест ждёт видимую комнату и статус сохранения; дальнейшие точные проверки неизменности не ослаблялись. Первые неуспешные запуски сохранены в [retry.log](retry.log) и [retry-green.log](retry-green.log).

Изменены только два browser-test файла: [SHA-256](changed-tests-sha256.json). Production-исходники совпадают с ведомостью предыдущей доставки. Полный вчерашний регресс не объявляется повторно выполненным сегодня; здесь выполнены указанные целевые проверки. Коммитов нет. UI-проверки проводятся в мобильной эмуляции Chrome, не на физическом телефоне владельца.
