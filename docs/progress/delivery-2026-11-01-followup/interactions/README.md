# Взаимодействия: меню, свойства стены и перенос проёмов

Новые четыре сценария `release-followup-interactions-e2e.spec.ts` проверяют меню поверх редактора без изменения его размеров, удержание/возврат фокуса, Escape и подложку; свойства стены только по явному действию, отсутствие разворота и нижнего удаления; перенос Door/Window с кратким подтверждением без полей, отменой, точными размерами, одной ревизией, Undo и повторным открытием.

[Начальный RED](initial-red.log) воспроизводит отсутствие модального меню и автоматическую плашку стены. Два других случая этого первого запуска остановились на преждевременном чтении сохранения в тесте и не считаются доказательством дефекта. После ожидания сохранённого проёма [отдельный RED](opening-red.log) воспроизводит именно отсутствие краткого подтверждения Door/Window. [Дополнительный RED фокуса](menu-focus-red.log) обнаружил, что закрытие меню перехватывало фокус у открываемых размеров плана; лишний ручной перевод фокуса удалён.

[GREEN: 4/4](green-browser.log). Удаление проходит прежнее подтверждение последствий для комнаты, а повторное открытие — через список проектов. Эти безопасные этапы не обходятся. Финальный полный прогон дополнительно включает усиленную проверку, что нажатие на подложку меню не снимает выбор стены.

## Проверка силы тестов

В отдельной копии исходников на порту 48179 автоматически внесены и выполнены пять дефектов:

1. Автоматическое появление панели стены после выбора.
2. Публикация переноса до подтверждения.
3. Публикация переноса по кнопке отмены.
4. Немодальное меню, оставляющее фон доступным.
5. Изменение ширины окна при переносе.

Все **5/5 обнаружены**. Перед внесением ошибок и после восстановления выполнены все четыре сценария: **4/4 PASS** в обоих случаях. [Машинный результат](fault-results.json), [исполняемый сценарий](run-faults.py), [SHA восстановленного исходника](source-sha256.json), [контрольный запуск](baseline.log), [повтор после восстановления](restored.log). Логи и точные замены каждого дефекта находятся рядом.

Это исполняемые проверки намеренно внесённых дефектов UI, а не общий Stryker mutation score. Рабочая копия и доступная владельцу production-сборка не инструментировались. Исторические SHA фиксируют этап проверки; финальная ведомость исходников находится в общем отчёте.

## Дополнительный контроль потери прав записи

Независимый просмотр нашёл активную кнопку подтверждения после перехвата writer lease. Добавлены два сценария в `release-followup-lease-e2e.spec.ts`: реальные две вкладки, Door/Window, точное сравнение Project, pointer и всех записей ревизий. [RED: 2/2](../regression/lease-red.log) показывает оставшийся диалог; [GREEN: 2/2](../regression/root-lease-green.log) подтверждает его закрытие при read-only, отсутствие воскресшего черновика после возврата writer и безопасную отмену нового переноса. Ошибка сохранения не считается read-only: её candidate остаётся в существующем восстановлении.
