Новые поведенческие проверки выполнялись сначала на неисправленной реализации (RED), затем после изменения (GREEN). Существующие браузерные сценарии обновлены только там, где запрос намеренно изменил контракт: удалены ожидания split-жеста, осевых фильтров, имён комнат и немедленной публикации перемещения проёма. Проверки геометрии, истории, отмены, восстановления и сохранения остаются.

Срезы с отдельными доказательствами:

- [Геометрия](geometry/README.md): 177 целевых модульных тестов, 4 мобильных браузерных сценария, Stryker 90,61%.

- [Каталог, удаление и метаданные комнат](catalog-controller/README.md): 138 целевых модульных тестов; Stryker 98,84% на изменённых ветках. Исходный более широкий прогон 83,20% сохранён в отчёте.
- [Восстановление проёмов](opening-recovery/README.md): три RED/GREEN-сценария подтверждают точный повтор записи без двойной публикации и зависшей модалки.

## Ограничения доказательств

Браузерные проверки выполняются в Chrome с эмуляцией телефона и настоящими touch events. Физические iOS/Android в этой среде не проверялись. Установка с домашнего экрана и аппаратный WebGL требуют отдельной проверки на устройствах; эмуляция не объявляется такой проверкой.

Покрытие измеряется командой `pnpm test:coverage`; это модульное V8-покрытие, без объединения с browser coverage. Наличие тестов не означает 100% покрытия приложения. Автоматические мутационные показатели относятся к перечисленным изменённым срезам; для интегрированного UI выполнены отдельные исполняемые fault-injection проверки.

Сетевую недоступность невозможно устранить как класс событий. Исправлены её представление, ограничение ожидания, отмена и повтор запроса; целостность и точное хеширование каталога не ослаблены.
