# Изолированные UI fault-injection проверки — 01.11.2026

Шесть явно заданных исполняемых дефектов внесены по одному в AppShell.tsx только в копии /tmp/interiors-ui-mutation-2026-11-01. Рабочий исходник не мутировался. До изменений и после точного восстановления выполнены 4сценария: REL-11,REL-14,REL-15-16,PHONE-FIX-07. Оба запуска 4/4 PASS; SHA исходника до/после совпадает.

|---|---|---|

Все 6 обнаружены поведенческими assertions, без ошибок компиляции, инфраструктурных timeout или умышленного синтаксического повреждения. Логи, патчи и[results.json](results.json) лежат рядом. Время исполняемых запусков суммарно 121,32 с, включая baseline/restored; отдельный case не более 19,42 с. Это не автоматический Stryker score и не процент покрытия всего UI.

Почему применён согласованный fallback: установленный Stryker command runner передаёт __STRYKER_ACTIVE_MUTANT__ в env дочернего Node-процесса; инструментированный runtime проверяет g.process.env. Существующий Playwright fixture не передаёт этот сигнал в browser global, где исполняется AppShell. Автоматический UI mutation pipeline потребовал бы отдельного проверенного bridge/harness; текущие Stryker-конфигурации предназначены для Rstest domain/application. В ограниченном срезе выполнены настоящие browser fault-injection проверки вместо недостоверного автоматического score.

Артефакты: [baseline](baseline.log), [restored green](restored-green.log), [source hashes](restored-source-sha256.txt), [runner](run-ui-faults.py). Исходный snapshot содержит только уже проверенные изменения; общий финальный регресс актуального дерева выполняется отдельно.
