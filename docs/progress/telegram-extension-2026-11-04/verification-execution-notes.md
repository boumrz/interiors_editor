# Verification execution rules learned from actual controls

These rules govern verification tooling. They do not change application behavior, scope, acceptance thresholds or existing test bodies.

- Compare the real paths of `process.argv[1]` and `import.meta.url` when deciding whether an ES module is the CLI entry point. macOS may supply `/var/...` or `/tmp/...` in argv and resolve the module through `/private/...`. Exercise the actual CLI through both aliases. Import-only tests do not detect a silently skipped entry point.
- A whole mutation report requires one actual baseline and exactly one actual command record for every pinned mutant ID. Verify the scope, profile hash, completed child CLOSE, named result and raw Killed/Survived status together. A successful process exit or JSON mutation report alone is insufficient.
- Wait for CLOSE, including inherited output streams, before restoring source or accepting terminal evidence. Keep stop requests sticky across awaited input checks and final report writes. Signals during finalization must produce an unqualified result.
- A direct child EXIT does not imply CLOSE: a descendant can retain its output pipes. A watchdog must re-attest current descendant identities and drain owned processes even after the leader exits. Never signal an unknown process based on a reused PID or bare process group. If an unknown holder prevents safe drain, terminate the parent-owned wait with explicit incomplete proof; preserve the unknown process and keep source restoration unproven until physical drain is established. Actual finite inherited-pipe controls must cover watchdog and manual stop.
- When checking for a vanished launcher, reread its same owning record after checking the current PID and command. A stale running record followed by a normal final write and EXIT is not an orphan.
- Restore only known original or independently generated official instrumented/noCheck bytes. Preserve unknown bytes, missing files and symlinks for review. Generated supervisor code belongs outside the input tree it freezes.
- Bind Playwright's raw reporter errors to every formatted JSON copy using the pinned formatter and actual CLI/case/worker identity. Only then apply recursive `errors`/`cause`, BODY, hook/finally and timeout checks. Do not reinterpret arbitrary error-message text as a stack.
- Validate an intended negative control using its actual raw witness. Exit99 or a generic invalid flag may result from an unrelated setup problem. Preserve genuine clean outcomes even when a proposed control was expected to fail.
- Keep fixture classes explicit. Real mounted UI with typed runtime doubles, actual IndexedDB, local Chromium and physical Telegram demonstrate different things. Do not claim an emitted-request ledger or separate channel timing when the packet has neither.
- Keep every rejected or partial report unchanged and unscored. Each accepted whole gate keeps its own source hash, inventory, fixed corpus, threshold and evidence. Do not merge scores from different scopes or source revisions.
- Reclaim only individually attested inactive generated caches or build duplicates whose exact bytes remain in a verified archive. Keep raw reports, traces, screenshots, source snapshots, delivered files and user storage. Record the exact removed paths and archive hashes; do not treat an `interiors-*` directory name alone as ownership.

Current application data, protected Web/PWA checks and delivered assets remain subject to the separate preservation audits. No verification preparation authorizes deployment, commits, cloud synchronization or Web/PWA retirement.
