## Доступность первичного текста

Первичные основания для статуса — карточки Росстандарта и [уведомление Института стандартизации о 21.101-2026](https://uvedns.gostinfo.ru/uveddetails?id=192190). Официальный просмотрщик полного текста оказался недоступен используемым средствам. Для правил прочитаны сами тексты стандартов в репродукциях официальных изданий, а не обзорные статьи:

- [2.307-2011, официальное издание 2020 года, копия на сайте ГУАП](https://docs.guap.ru/regdocs/stands/gost_2-307-2011_ver-2020.pdf). Последующая [поправка ИУС 1-2021](https://protect.gost.ru/gost/changesdetails/52ab9b68-2746-42e5-9dbf-949a3c60b8bf) есть в официальной карточке; её полный текст не получен.
- [21.501-2018, официальное издание 2019 года, репродукция PDF](https://gostam.ru/pdfs/gost-21-501-2018.pdf).
- [21.101-2026, копия издания на сайте Фонда капитального ремонта Санкт-Петербурга](https://www.fkr-spb.ru/upload/iblock/f06/0bbjtamv5nda270vffs1wmoxbuz7vd4w.pdf), найденная через [нормативную библиотеку фонда](https://www.fkr-spb.ru/podrad/regulatory-documentation/). Получены титул, содержание и реквизиты; извлечение страниц раздела 5.4 нестабильно. Рабочая сверка пунктов 5.4.1–5.4.2 по доступным электронным репродукциям согласуется с предыдущими правилами, но проверкой полного действующего официального оригинала с поправкой её считать нельзя.

Таким образом, полная нормативная верификация последней редакции не заявляется. Этот предел не мешает выбрать привычную размерную графику для бытового планировщика; обещать полноценный выпуск рабочей документации на этом основании нельзя.

## Правила, полезные для профиля

**Единицы и засечки.** СПДС 21.101-2026, 5.4.1–5.4.2: для обычного плана — миллиметры без повторения единицы возле числа; линейные окончания — правые засечки 45°, длиной 2–4 мм на листе; продолжение размерной линии за крайние выносные — 0–3 мм. Стрелки относятся, в частности, к угловым, радиусным и диаметральным размерам. Это разные случаи, поэтому не требуется рисовать стрелки у каждой стены. Источник статуса — [Росстандарт](https://protect.gost.ru/gost/details/17bc12e8-6579-4145-b141-56855e772e7f); предел проверки текста указан выше.

**Линии и чтение.** 2.307-2011: 5.2 — размерная линия параллельна измеряемому отрезку, выносные перпендикулярны; 5.9–5.14 — предпочтение внешнему размещению, выход выносных на 1–5 мм, минимумы 10 мм от контура и 7 мм между параллельными размерными на листе, избегание пересечений; 5.24–5.31 — число около середины над линией, читаемая ориентация по рисунку 32, разнесение/выноска при тесноте, отсутствие линий поверх текста. 4.7 — линейные числа в мм без единицы; 4.13 отдельно допускает строительную замкнутую размерную цепь. Упомянутые миллиметры графики относятся к документу, не к длине стены. Универсальное требование зазора 1–2 мм между контуром и началом выносной линии в проверенных пунктах не найдено. [Первичный текст 2.307](https://docs.guap.ru/regdocs/stands/gost_2-307-2011_ver-2020.pdf).

**Состав размеров плана.** 21.501-2018, 5.3.2а–б: межосевые/общие осевые расстояния, толщина и привязка стен, необходимые размеры и привязки проёмов; примеры планов — приложение Б. Из этого не следует универсальная обязанность любого мобильного приложения иметь ровно три наружные цепи. Цепочка «простенок — проём — простенок» плюс отдельный общий размер — выбранная здесь практическая раскладка. [Первичный текст 21.501](https://gostam.ru/pdfs/gost-21-501-2018.pdf).

## Политика для телефона — решение продукта

1. Значения вычисляются из текущего immutable Project/preview. Размерные объекты — disposable projection: они не записываются в Project, Revision, историю или backup. UI не исправляет вершины для красивого числа.
2. У каждого размера явно задана база: `axis`, `clear` или `outer`. Осевая длина стены не называется размером в чистоте. Общий размер между крайними осями также не называется наружным габаритом здания. Для осевых цепей в UI требуется видимая подпись «по осям».
3. Внутренние размеры прямоугольной комнаты берутся из usable polygon после inward offset. Для L-плана или комнаты с отверстиями не подставляется bounding box как ширина/глубина помещения: показываются доказуемые участки границы/пролёты либо только доступная информация. Другая комната и отверстие не считаются свободным пространством.
4. Цепь проёмов использует одну wall-local базу. Начало/конец проёма — `offsetMm ± widthMm/2`; простенки вычисляются между соседними интервалами. Нулевой простенок не подписывается, совпадающие засечки объединяются. Это размер геометрического проёма модели, а не автоматически ширина дверного полотна или фактический световой проход после отделки.
5. Диагональная линия идёт вдоль стены, её число — длина отрезка, а не проекция на X/Z. Направление текста нормализуется, без перевёрнутых надписей; вертикальный текст читается снизу вверх. Точные значения сохраняются до общего правила округления. Сумму округлённых подписей нельзя подгонять изменением последнего простенка.
6. DrawingDimensions-RU меняет только оформление числа: `3200`. Общая легенда — «Размеры в миллиметрах». В numeric inputs, aria и справочной информации остаются единицы. Точность общего formatter не меняется.
7. Начальная экранная настройка: текст 14 CSS px, засечка около 10 px, расстояние до первой внешней линии около 40 px, шаг рядов 28 px. Это UI-параметры с проверкой на телефоне, не гарантированный физический масштаб ГОСТ. При обычном обзоре предпочтительны общий размер и выбранная цепь, максимум два ряда на сторону; тесные локальные числа выносятся и раскрываются увеличением. Геометрия не скрывается и не меняется.
8. Размерная графика не перехватывает жесты стены/проёма/предмета. Коллизии текста решаются в экранных координатах после zoom/pan с учётом шапки, dock и маркеров. Приоритет: активный объект, его цепь, выбранная комната, общий габарит, остальные подписи. Маленький шрифт вместо решения коллизии не применяется.

## Связь с действующими контрактами

- `geometry-contract.md:32–61`: целые канонические концы для 45°, общий exact measurement/half-up, V1 с «мм». S6 явно вводит отдельный суффиксный профиль для чертёжных подписей; численное округление остаётся тем же.
- `geometry-contract.md:89–94`: стены — centerlines, полезный контур комнаты — inward offset, а не второй источник геометрии.
- FR-13, CAP-3, AD-1/AD-2/AD-20: revision-bound измерения, отделение domain от UI, отсутствие обратной записи округления.
- `room-measurement.ts` уже не придумывает прямоугольные габариты для polygonal room. `PlanProjection.tsx:2986` пока показывает комнатную подпись, а не полноценную систему цепей.

Перед реализацией согласуется чистый API dimensions helper; создание canonical CAP/FR/AD или изменение SPEC.md вручную не требуется.
