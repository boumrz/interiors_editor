# Двухчасовая статистика открытий Telegram Mini App

Статус — утверждено владельцем 24 ноября 2026 года. Связи — CAP-13, FR-61,
NFR-29, AD-34 и Story 10.18.

## Результат

Владелец видит в Яндекс Метрике число обычных открытий мобильного
редактора за каждые завершённые два часа по Москве. Новая сумма появляется
после окончания интервала и обработки Метрикой. Суточный ряд сохраняет
историю, а добровольный подсчёт повторов ведётся по прежним условиям.

На сервере действуют суточная таблица и повторные попытки отправки с 00:05
до 11:05. Времени отдельных запросов в таблице и журналах нет. Двухчасовой
ряд начинается с первого полного интервала после включения новой версии.

## Срез выпуска

1. Обычный проверенный вход из Telegram на iOS или Android отправляет один
   пустой запрос вместо прежнего сигнала. Коллектор одним действием
   увеличивает суточную сумму и сумму интервала. Признак мобильного клиента
   используется локально для выбора канала и передаётся только как тип
   общего запроса. Переключатель статистики продолжает управлять обоими
   итогами обычных открытий. Маршрут повторов и его отдельное согласие
   сохраняются. Старые клиенты могут заполнить только прежний суточный ряд.
2. Один отчёт на завершённый интервал по Москве отправляется с отдельным
   ключом `tma_opens_2h` и постоянным техническим идентификатором ряда.
   Общий суточный экспорт остаётся независимым. При подтверждённом отказе
   возможна повторная попытка в пределах окна провайдера. Неопределённую
   отправку оператор сначала сверяет с отчётом. Открытый интервал и периоды
   до включения не публикуются. Для полного учтённого интервала возможен ноль.
3. В счётчике `114493478` создать отдельный отчёт открытий за два часа.
   Суточный отчёт фильтровать по `tma_opens`, повторы по `tma_repeat_opens`,
   двухчасовой по `tma_opens_2h`. Если кабинет не поддерживает нужный шаг,
   использовать подтверждённую почасовую группировку API с объединением
   соседних часов. Проверить раздельную атрибуцию в суточном отчёте и новом
   ряду до публикации. В отчётах указывать московское время.
4. До включения опубликовать уточнение политики и отразить решение в
   требованиях и архитектуре. Хранить только общий итог на интервал. Метрика
   получает сумму, время интервала и технические параметры отчёта. Пользовательские
   идентификаторы, IP посетителя, платформа поимённо и данные проектов в
   отчёт не попадают. Откат выключает дополнительную отправку и сохраняет
   состояние доставки и прежние суточные итоги.

## Проверка

- TDD для границ чётного часа и полуночи, входа с отключённой статистикой,
  непустого запроса, старой SQLite, параллельной записи и повтора отправки.
- Проверить на iOS и Android по доступным реальным клиентам или явно
  обозначить эмуляцию. Один новый вход меняет два агрегата ровно на один.
- Сопоставить значения двух фактических полных интервалов между SQLite и
  отчётом Метрики. Проверить, что текущий интервал виден как незавершённый
  либо отсутствует, а старые сутки сохранили исходные итоги. Контрольные
  синтетические сигналы в рабочий отчёт не отправлять.
