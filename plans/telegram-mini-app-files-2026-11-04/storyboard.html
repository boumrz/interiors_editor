Копия проекта остаётся у пользователя

Проверяем путь от сохранённого проекта до отдельного файла и новой локальной копии.

Действующий Web/PWA сохраняет прежние импорт и экспорт. Новый маршрут выбирается явно. Здесь собраны утверждённые состояния и вопросы к реализации; эта страница не подтверждает выпуск, физический перенос или сохранение файла системой.

Путь и границы

Сохранённый проект
  └─ Подготовить полную копию → [отмена / ошибка: проект не меняется]
       └─ Файл готов → явное «Передать файл»
            ├─ Отменено / Не удалось передать / Способ недоступен → повтор или выход
            └─ Проверьте файл вне приложения
                  └─ выбрать внешний .interiors
                       ├─ Проверка недоступна → исходный файл не изменён
                       ├─ Установленный отказ → исходный файл не изменён
                       └─ полная проверка + atomic save → НОВЫЙ локальный проект

Существующие поверхности

Исторические визуальные материалы — только контекст общей оболочки. Действующий UX-контракт и текущий код имеют приоритет; старые кнопки и панели отсюда не восстанавливаются.

Переходы, требующие проверки

  • Подготовка и системная передача разнесены, чтобы новая явная кнопка сохраняла пользовательское действие для Web Share.
  • Закрытие, смена аккаунта и поздний результат не показывают файл из предыдущего runtime.
  • Кнопки и фокус не создают незапрошенную команду из незавершённого ввода; это проверяется вместе с общим guard Back/Close.
  • Callback share/download не становится доказательством внешнего сохранения.

🆕 Недостающие представления

Рутинные решения ниже основаны на уже согласованном контракте; отдельное разрешение на upload, изменение прежнего экспорта или удаление Web/PWA отсутствует.

НУЖЕН РАБОЧИЙ КОМПОНЕНТ

Файл готов к передаче

  • Где появляется? Из действия полной копии сохранённого Project.
  • Какой вид? Общая компактная поверхность с существующими токенами и управлением фокусом.
  • Какие действия? Явная передача и отмена; имя файла видно.
  • Что при смене runtime? Отозвать операцию и убрать старую поверхность.

НУЖЕН РАБОЧИЙ КОМПОНЕНТ

Результат системного действия

  • Какой текст? «Проверьте файл вне приложения», пока внешнее сохранение не доказано.
  • Какие ошибки? Отменено, не удалось передать, способ недоступен.
  • Как повторить? Сохранить подготовленный локальный файл и предложить явный повтор.
  • Есть ли обход через сервер? Нет.

НОВЫЙ ЯВНЫЙ WEB/PWA МАРШРУТ

Импорт файла для переноса

  • Где? Рядом с прежним импортом в Projects; старое действие сохраняется.
  • Кто выбирает маршрут? Пользователь; файл не включает fallback.
  • Как хранится результат? Новый Project ID после полной проверки и атомарного сохранения.
  • Что если проверка недоступна? Так и сообщить, исходный файл не изменять.

ОТДЕЛЬНЫЙ СМЫСЛ

Данные для восстановления

  • Это полная копия? Нет, несохранённый candidate остаётся recovery draft.
  • Какое имя? Отдельное расширение .interiors-recovery.json.
  • Когда появляется «Сохранено»? Только после успешной новой Durable публикации.
  • Какой перенос? Локальная выдача и явный выбор файла.

Соседние состояния

Projects, редактор плана, ошибка сохранения и readonly recovery остаются существующими поверхностями. Каталог, оплаты, синхронизация и отправка боту не добавляются этим потоком.

Последовательность проверки

  1. Сверить решения с UX/SPEC и существующей оболочкой.
  2. Воспроизвести отсутствующее поведение в проверке интерфейса.
  3. Добавить минимальные состояния и проверить фокус, отмену, повтор и смену runtime.
  4. Пройти реальный ZIP → выдача → повторный выбор → новый Project без дрейфа размеров.
  5. Повторить Web/PWA regression; физическую iOS/Android проверку вести отдельно.

AD-31: две локальные области в одном списке

Макеты для новой изолированной области. Она используется только явно выбранным и проверенным импортом; новое хранилище получило допуск к локальной реализации, но ещё не включено. Прежние проекты, импорт, экспорт и PWA сохраняются. Имена и даты здесь демонстрационные.
