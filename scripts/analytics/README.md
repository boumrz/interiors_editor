# Статистика открытий Telegram Mini App

Сборка использует пустые запросы на собственный Telegram-домен. Подсчёт открытий включён по умолчанию. Пользователь может выключить статистику до первого учитываемого входа или позднее в настройках. Для учёта повторных открытий на том же устройстве требуется отдельное разрешение. Приложение определяет повтор локально. Запросы относятся к входу в редактируемый Telegram-редактор. Простое чтение документов, просмотр прежних проектов и Web/PWA их не создают.

| Публичный путь на domiknote.ru | Что прибавляет приёмник |
| --- | --- |
| `POST /stats/tma-open-v2` | Одно открытие к сумме за текущий московский день. |
| `POST /stats/tma-mobile-open-v1` | Одно открытие к суточной сумме и, с начала двухчасового учёта, к текущему интервалу по Москве. Новая версия выбирает этот путь для проверенного редактируемого входа из Telegram на iOS и Android. |
| `POST /stats/tma-repeat-v2` | Одно добровольно учитываемое повторное открытие к отдельной сумме за этот день. Приём прекращается при досрочном отключении исследования и с 00:00 МСК 1 апреля 2027 года. |

Nginx пересылает запрос через Unix-сокет, задаёт служебный заголовок Host, нулевую длину и закрытие соединения. Заголовки клиента и тело до коллектора не доходят. Прежние POST на `/stats/tma-open`, `/stats/tma-return` и `/stats/tma-return-v2` закрыты. На входе HTTPS инфраструктуре по-прежнему технически доступен сетевой адрес. Настройки журналирования у хостинга подлежат отдельной проверке. Сервер принимает пустые сигналы и не подтверждает личность посетителя. Суточные суммы не дают числа уникальных людей или межустройственного удержания.

## Установка и переход

Установку выполняет администратор действующего сервера из проверенного коммита перед обновлением Nginx и клиентской сборки. Действующая команда ограниченного SSH-получателя переносит только frontend и каталог. Она проверяет приватный `GET /health/aggregate-v2` до переключения публичных файлов. Эта проверка читает обе таблицы и проверяет конфигурацию назначения. Доступ к токену Яндекса и факт уже доставленного суточного отчёта подтверждаются отдельно.

1. Сохраните штатную резервную копию SQLite, включая состояние отправки. Установщик оставляет текущие суммы, маркеры отчётов и существующий защищённый файл `/etc/interiors-analytics/service.env`.
2. В каталоге `scripts/analytics` выполните `sudo sh install.sh`. Скрипт атомарно заменяет Python-файл и unit-файлы, обновляет systemd, запускает сокет, перезапускает коллектор и включает суточный таймер. В существующей БД коллектор в одной транзакции создаёт таблицу `repeat_counts`, сохраняя таблицы `counts` и `exports`. Повторная установка безопасна.
3. В защищённом файле открытий нужны `INTERIORS_MP_AGGREGATE_COUNTER_ID` и `INTERIORS_MP_AGGREGATE_TOKEN`. Для новой установки целевой счётчик задан как `114493478`, токен администратор заполняет локально. После изменения файла выполните `sudo systemctl restart interiors-analytics.service`. Службы исключают из своего окружения старые ключ псевдонимов и токен индивидуального счётчика. Порядок работы с историческими данными и ключами согласуется отдельно.
4. Прежде чем переключать сайт, проверьте `sudo curl -fsS --unix-socket /run/interiors-analytics/collect.sock http://localhost/health/mobile-open-v1` и `systemctl is-active interiors-analytics.socket interiors-analytics-daily.timer`. Ответ 204 проверяет схему, конфигурацию назначения и доступность нового маршрута без прибавления открытия. Обновите ограниченный SSH-получатель командой `python3 scripts/deploy/configure_github.py --install-receiver-only`, чтобы при выпуске он установил HTTPS-маршрут и проверил готовность коллектора. При откате оболочки оставьте рабочую версию агрегирующего коллектора.
5. Проверьте две суточные суммы командой `sudo -u interiors-analytics /usr/bin/python3 /usr/local/lib/interiors-analytics/collector.py report --day YYYY-MM-DD`. Первое фактическое получение отчёта Яндексом сверьте после завершения дня. Публикация каталога с изменившимся seed имеет собственный порядок.
6. После публикации новой политики по адресу `/legal/2026-11-24.1/privacy-policy.html` и проверки настроек отчёта Метрики запустите `sudo -u interiors-analytics /usr/bin/python3 /usr/local/lib/interiors-analytics/collector.py activate-intraday`. Команда фиксирует первую полную границу и при повторе возвращает её. Вызовите `sudo systemctl enable --now interiors-analytics-intraday.timer`. До активации новый маршрут учитывает только суточную сумму. Таймер установлен отдельно и при установке коллектора остаётся выключенным.

При независимом досрочном завершении исследования задайте `INTERIORS_REPEAT_ENABLED=0` в файле службы и перезапустите коллектор. Для остановки приёма и экспорта открытий и повторов используйте `INTERIORS_AGGREGATE_AUTHORIZED=0`. Для полной остановки задайте также `INTERIORS_PRODUCT_METRICS_ENABLED=0`. После отключения обязательной статистики новые публикации потребуют восстановления приёмника. Ранее доставленные отчёты и старые псевдонимные события остаются у соответствующих получателей до исполнения применимых процедур.

## Экспорт и доказательства

Суточный таймер после полуночи по Москве отправляет один просмотр служебной страницы с постоянным техническим ClientID отчёта и двумя числовыми параметрами `tma_opens` и `tma_repeat_opens`. Между пользователями не устанавливается соответствие. До включения нового выпуска историческая сумма повторов в этой схеме отсутствует. Сверяйте начало периода с датой фактического развёртывания. Уже отправленные дни не пересылаются.

SQLite резервирует отправку и получает обе суммы в одной транзакции. После подтверждённого отказа получателя или сбоя до подключения отправку можно повторить в 12-часовом окне. Неопределённый результат и аварийная отметка `sending` требуют сверки оператором перед любыми дальнейшими действиями. Локальные итоги сохраняются.

Двухчасовой таймер запускается в пять минут каждого часа. Новая сумма
отправляется после завершения чётного интервала по Москве. Промежуточные
запуски позволяют повторить прерванную до приёма отправку. У ряда отдельный
постоянный служебный ClientID и параметр `tma_opens_2h`. Метрика получает
техническое время последней секунды интервала. История прежних суток
доступна в исходной детализации.

`sudo -u interiors-analytics /usr/bin/python3 /usr/local/lib/interiors-analytics/collector.py report-intraday --day YYYY-MM-DD`
показывает закрытые интервалы с момента наблюдения и состояния доставки.
Запись с нулём означает полностью учтённый интервал. Открытый интервал и
время до включения отсутствуют. `pending` означает, что нет записи об
отправке. Через 12 часов неотправленные окна отмечаются как `expired`.
Сверяйте время и число
с отчётом Метрики. Для остановки дополнительных отправок выполните
`sudo systemctl disable --now interiors-analytics-intraday.timer`. Суточная
служба и сбор в таблицу интервалов продолжат работу. Собранные интервалы и
история доставки сохранятся. Это отдельный откат отправки статистики. Для
возврата к прежней оболочке потребуется оставить совместимый маршрут и
выключить двухчасовой таймер. Старые клиенты передают только суточные открытия.
При перерыве в мобильном сборе оставьте таймер выключенным до восстановления
новой оболочки и истечения окна доставки за последний неполный интервал.
Отметьте неполные интервалы в операторском отчёте.

## Суточная продуктовая статистика мобильного редактора (v1)

Пустой `POST /stats/tma-editor-v1/{ios|android}/{код}` увеличивает сумму за
московский день. Список кодов закрыт. Nginx передаёт в приватный сокет
фиксированный путь, `Host: localhost`, `Content-Length: 0` и `Connection: close`.
Таблицы продуктовых сумм и статусов доставки создаются при запуске рядом
с действующими данными открытий. В исходном состоянии новый канал выключен.

1. Установить совместимый коллектор с `INTERIORS_PRODUCT_METRICS_ENABLED=0`
   в защищённом `/etc/interiors-analytics/service.env`. Установщик сохраняет
   целиком уже существующий файл. При отсутствии строки действует значение
   `0`. Старые открытия и повторы продолжают обрабатываться.
2. Проверить приватный протокол до выкладки клиента. Код `204` подтверждает
   схему хранения и настройку счётчика `114493478` даже при выключенном сборе.
   Проверка проходит без записи посещений.
3. Опубликовать Mini App и согласованные документы RU/EN. Архив с согласованным
   текстом `/legal/2026-11-25/product-analytics-consent.html` проходит отдельную
   проверку приватного протокола и получает закрытый список маршрутов Nginx.
4. После приёмки документов, согласия и настроек отчётов установить
   `INTERIORS_PRODUCT_METRICS_ENABLED=1` через `sudoedit` и перезапустить только
   `interiors-analytics.service`. Действующий ежедневный таймер прочитает то
   же значение при следующем запуске.
5. При откате установить `INTERIORS_PRODUCT_METRICS_ENABLED=0` и перезапустить
   службу. Суммы и состояния доставки сохраняются. Архив предыдущей версии
   можно опубликовать после отключения. Он использует собственный список
   маршрутов независимо от документов, сохранённых в пуле.

```sh
sudo curl -sS -o /dev/null -w '%{http_code}\n' --unix-socket /run/interiors-analytics/collect.sock http://localhost/health/tma-editor-v1
sudoedit /etc/interiors-analytics/service.env
sudo systemctl restart interiors-analytics.service
```

Ежедневный таймер отправляет до шести продуктовых отчётов за закрытый день
независимо от состояния отчёта открытий. Для каждой пары адрес
`https://domiknote.ru/tma-editor-report/{группа}/{платформа}` и служебный
ClientID фиксированы. Параметры содержат суммы по кодам своей группы.

| Группа | iOS | Android |
| --- | --- | --- |
| `projects` | `7000000000000000003` | `7000000000000000004` |
| `tools` | `7000000000000000005` | `7000000000000000006` |
| `errors` | `7000000000000000007` | `7000000000000000008` |

Первый день с учтённым сигналом может быть неполным. Открытый день виден
в локальном отчёте, а отправка начинается после полуночи по Москве. Сверяйте
суммы после появления принятого периода в Метрике. До первого закрытого
периода укажите ожидание данных. Нулевые суммы в согласованном рабочем периоде
отражают отсутствие сигналов. Отмечайте периоды отключения канала отдельно.
После перехода на двухчасовой канал ежедневный таймер завершает только
дни с принятыми сигналами v1 или существующим журналом выгрузки.

```sh
sudo -u interiors-analytics /usr/bin/python3 -B /usr/local/lib/interiors-analytics/collector.py report-product --day YYYY-MM-DD
```

Для `unknown` или оставшегося после остановки `sending` сначала убедитесь,
что выгрузка завершилась, и сверьте конкретную пару с ответом получателя.
После подтверждения зафиксируйте `sent` для принятого отчёта либо `rejected`
для гарантированно отсутствующего. Вторая отметка допускает только штатный
повтор в пределах 12-часового окна. Полученный отчёт и другие пары остаются
в журнале. Испытательные сигналы и отчёты используйте с временным
хранилищем и тестовым получателем.

```sh
sudo -u interiors-analytics /usr/bin/python3 -B /usr/local/lib/interiors-analytics/collector.py resolve-product --day YYYY-MM-DD --group projects --platform ios --confirmed sent
```

## Двухчасовая продуктовая статистика мобильного редактора (v2)

Релиз с редакцией согласия `2026-11-25.2` принимает
`POST /stats/tma-editor-v2/{код}`. Платформа остаётся на устройстве.
Суммы и журнал v2 хранятся в новых таблицах. Ежедневные суммы и журнал v1
остаются доступными для сверки.

Перед выпуском установить обновлённый коллектор и проверить приватный
протокол. Существующий флаг `INTERIORS_PRODUCT_METRICS_ENABLED` управляет
обоими продуктовыми протоколами, наблюдение обычных открытий продолжает
работать. Таймер `interiors-analytics-intraday.timer` в 05 минут каждого часа
обрабатывает двухчасовые открытия и продуктовый поток независимо.

```sh
sudo curl -sS -o /dev/null -w '%{http_code}\n' --unix-socket /run/interiors-analytics/collect.sock http://localhost/health/tma-editor-v2
sudo systemctl list-timers interiors-analytics-intraday.timer
```

Выгружаются закрытые окна, в которых принят хотя бы один сигнал v2.
Первое записанное окно может быть неполным. Три отдельные записи имеют
время последней секунды окна и постоянные служебные ClientID.

| Группа | Адрес | ClientID |
| --- | --- | --- |
| `projects` | `https://domiknote.ru/tma-editor-report/projects/mobile` | `7000000000000000009` |
| `tools` | `https://domiknote.ru/tma-editor-report/tools/mobile` | `7000000000000000010` |
| `errors` | `https://domiknote.ru/tma-editor-report/errors/mobile` | `7000000000000000011` |

Чтение по дню показывает закрытые окна. Пустой список `reports` в окне
означает отсутствие исходных сигналов; у записанного окна видны суммы и
статусы трёх групп. `firstWindow` отмечает первое записанное окно.
Для одного окна используйте его точное начало со смещением часового
пояса. После сверки получателя и завершения текущей выгрузки оператор
может зафиксировать состояние конкретной группы. Подтверждённое отсутствие
разрешает штатный повтор только в пределах 12-часового окна. Полученная
и неопределённая отправки сохраняют свои статусы до сверки.

```sh
sudo -u interiors-analytics /usr/bin/python3 -B /usr/local/lib/interiors-analytics/collector.py report-product-intraday --day YYYY-MM-DD
sudo -u interiors-analytics /usr/bin/python3 -B /usr/local/lib/interiors-analytics/collector.py report-product-intraday --start YYYY-MM-DDT22:00:00+03:00
sudo -u interiors-analytics /usr/bin/python3 -B /usr/local/lib/interiors-analytics/collector.py resolve-product-intraday --start YYYY-MM-DDT22:00:00+03:00 --group projects --confirmed sent
```

Для отката сначала выключить продуктовый флаг и перезапустить
`interiors-analytics.service`. Прежний архив восстанавливает маршруты v1.
Двухчасовые суммы и журнал остаются в той же базе.

Из корня репозитория можно проверить настоящее сокетное приложение, совместимость прежней базы, правила Nginx и форму отчёта без внешней отправки. Для HTTP-проверки требуется Nginx в PATH или путь в переменной `INTERIORS_NGINX_BIN`.

```sh
python3 -m unittest discover -s scripts/analytics -p 'test_*.py'
python3 -m unittest discover -s scripts/deploy -p 'test_*.py'
```
